# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Сайт-портфолио фотографа с клиентскими альбомами: Flask + MySQL (PyMySQL), шаблоны Jinja, ванильные JS/CSS. Комментарии в коде и тексты интерфейса на русском, пишите так же.

## Запуск и деплой

- Зависимости: `pip install -r scr/requirements.txt`.
- Секреты берутся из `scr/.env` (он в `.gitignore`) через `scr/config.py`: `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_PORT`, `DB_NAME`, `FLASK_SECRET_KEY`. Если какой-то из обязательных не задан, импорт `config` падает с `RuntimeError`. Образец — `scr/.env.example`.
- Локальный запуск: `cd scr && FLASK_DEBUG=1 python __init__.py`. Нужна доступная MySQL-база. Модули внутри `scr/` импортируют друг друга как верхнеуровневые (`from config import ...`), поэтому `scr/` должна лежать в `sys.path`.
- Прод: shared-хостинг с cPanel и Passenger (`.htaccess`, `passenger_wsgi.py`, `from scr import app as application`). Перезапуск делается через `touch tmp/restart.txt`. На хостинге переменные окружения задаются в «Setup Python App». Файлы заливаются по FTP через VS Code SFTP (`.vscode/sftp.json`).
- **GitHub** (публичный репозиторий `photographer-portfolio`): в git НЕ попадают `.htaccess` и `passenger_wsgi.py` (в путях логин аккаунта хостинга — в репозитории их образцы `*.example` с `<логин>`), `.vscode/` (пароль FTP), `.env`, `scr/static/uploads/` (фото клиентов), дамп БД, `public_html/`, `.claude/`. Из `db/` в git идут только `schema.sql` (структура без данных) и SQL-изменения `db/20*.sql`. Новые служебные и секретные файлы сразу дописывай в `.gitignore` (и в `ignore` `sftp.json`, если их не надо заливать по FTP). Логин аккаунта хостинга, реальные контакты и данные из дампа в коммиты не писать.
- Папка `venv/` в корне скачалась с хостинга по FTP. Это серверное окружение под Linux (python3.10), на Windows оно не запустится, и править его не нужно.
- Тестов, линтера и сборки нет.
- Хостинг Beget, MySQL, база `<логин>_photo`. Изменения схемы применяются вручную через phpMyAdmin. SQL новых изменений кладётся в `db/ГГГГ-ММ-ДД_что.sql`. Их нужно выполнить ДО заливки кода, который на них опирается.
- `scr/backfill_compress.py` — разовый идемпотентный скрипт, который пересжимает уже загруженные обложки и фото направлений. Упомянутые в нём миграции уже применены.

## Схема БД

Дамп лежит в `db/localhost.sql` (экспорт из phpMyAdmin). В нём есть **реальные данные**: хэш пароля, контакты клиентов, токены. Поэтому дамп исключён из git и FTP-синхронизации. Схему читайте оттуда, но не копируйте из него данные в код и ответы. В git — `db/schema.sql`: только структура таблиц из дампа (без INSERT); SQL-изменения после дампа — отдельными файлами `db/ГГГГ-ММ-ДД_*.sql`.

- `users`: админ сайта, в коде всегда `id = 1`. Хранит логин, `hash_password` (werkzeug), аватар, `watermark_text`, отдельное фото для «Обо мне» (`about_photo_url`/`about_photo_thumb_url`) и его точки фокуса для ПК и телефона (`about_focus_x/y`, `about_mobile_focus_x/y`, 0–100; `db/2026-10-07_users_about_photo.sql`), объём диска на тарифе `storage_limit_gb` (`db/2026-10-18_users_storage_limit.sql`). Таблица `role` к нему привязана, но в коде не используется: это задел на будущее клиентские аккаунты (например, запись на съёмку). Не трогать и не удалять.
- `photo_album` → `photo` (ON DELETE CASCADE). Альбом ссылается на `category` и `users` (RESTRICT, поэтому категорию с альбомами удалить нельзя). `photo.grid_class_id` → `grid_class` (`ratio-hor`/`ratio-ver`/`ratio-sq`).
- `client_sessions.access_token` ссылается на `photo_album.access_token` (UNIQUE), а не на id. `ON UPDATE` не каскадный, поэтому перед сменой токена старые сессии нужно удалить (так делает `api_regenerate_token`). `client_selections` → `photo` и `client_sessions.session_uuid`, у обеих ссылок CASCADE, пара `(photo_id, session_uuid)` уникальна. `client_sessions.pd_consent_at` и `pd_consent_version` хранят момент согласия на обработку ПД и редакцию его текста. Обе колонки добавлены после дампа, см. `db/2026-09-28_pd_consent_at.sql` и `db/2026-10-02_pd_consent_version.sql`. `client_name` и `client_contact` вводит посетитель, поэтому в админке их выводить только через `textContent`/`innerText`, никогда не через `innerHTML`.
- `photo.original_filename` — точное имя файла с компьютера фотографа (с кириллицей), пишется при загрузке (`db/2026-10-05_photo_original_filename.sql`). Нужно, чтобы найти отобранные клиентом фото среди RAW: «Выбор клиентов» показывает имя без расширения. У старых фото там NULL, и имя восстанавливается из `file_url` (`_original_photo_name`: срезается случайный префикс, но кириллица там уже транслитерирована).
- `directions` (главные «направления» на главной) → `category` (RESTRICT).
- `social_media` → `users` и `icon_social_media`. `achievements` → `users`. `services` и `retouch_sliders` ни на что не ссылаются.
- Почти везде есть поле `sort_order`. Поля мобильного кропа в фото, обложке и направлениях: `*focus_x/y` (0–100) и `*zoom` (decimal 3,1). EXIF хранится строками, уже отформатированными для показа (`1/320`, `f/1.8`, `+0.7 EV`, `Со вспышкой`). Список полей повторяется в `extract_exif_data`, загрузке, `api_update_photo`, `api_recompute_exif`, `api_get_album`, `album_detail` (exif_json), в `album.html`/`album.js` и в модалке ⓘ (`admin.html`/`admin.js`). Новое поле нужно добавить во все эти места.

## Архитектура

- Всё серверное приложение лежит в одном файле `scr/__init__.py` (~2500 строк), без blueprints и ORM. Каждый роут сам открывает соединение `get_db_connection()` (DictCursor), пишет сырой SQL и закрывает соединение в `finally`.
- **Публичная часть:** `/`, `/gallery`, `/about`, `/album/<slug>`. `inject_site_globals` (context_processor) на каждой публичной странице подгружает владельца сайта (`users.id = 1`) и соцсети для `base.html`. На `/admin*` и `/api/admin*` он пропускается.
- **Админка:** одна страница `/admin` (`templates/admin.html` + `static/js/admin.js`). Правки идут через JSON API `/api/admin/...`, часть действий отправляется обычными формами на `/admin/.../create|edit|delete`. Доступ закрывает `require_admin_login` (`before_request`): если нет `session['admin_id']`, API отвечает 401, а страницы редиректят на логин. Новые админские роуты должны начинаться с `/admin` или `/api/admin`, иначе они окажутся без защиты.
- **Сущности:** альбомы (`photo_album`), фото (`photo`), категории, направления (`directions`), услуги, ретушь, достижения, соцсети. Порядок везде хранится в поле `sort_order` и меняется через пары эндпоинтов `.../reorder` и `.../<id>/sort`.
- **Кэш CSS/JS:** `_static_cache_bust` (`@app.url_defaults`) дописывает к `url_for('static', ...)` `?v=<время изменения файла>` — после заливки браузеры сразу берут новые стили и скрипты (раньше держали старые до Ctrl+F5). Файлы из `uploads/` без версии: имена уникальные. Свои CSS/JS подключать только через `url_for`, не прямым адресом.
- **Файлы:** хранятся в `scr/static/uploads/`, в БД лежат пути относительно `static/` (`uploads/albums/...`), в шаблонах их выводит `media_url()`. Фото альбома раскладываются по `uploads/albums/{slug}_{id}/` в подпапки `full/`, `thumb/`, `watermarked/`, `cover_full/`, `cover_thumb/`, `cover_mobile/`. Имя папки зависит от slug и id, поэтому при смене slug альбома нужно переносить и файлы.
- **Обработка изображений (Pillow):** при загрузке снимаются EXIF, строится миниатюра, по пропорциям выбирается `grid_class` (`ratio-hor`/`ratio-ver`/`ratio-sq`), а если у альбома включён `is_watermark_enabled`, накладывается водяной знак с текстом из `users.watermark_text`. Для обложек и направлений делается мобильный кроп 9:16 с фокусом (`focus_x/y`, `zoom`).
- **Клиентские альбомы:** приватный альбом открывается только по `?token=<access_token>`, без токена отдаётся 404. Отбор фото клиентом (`allow_selection`) хранится в таблицах `client_sessions`/`client_selections`, клиента узнают по cookie `cs_<album_id>`. Удаление альбома каскадом (ON DELETE CASCADE) чистит связанные таблицы, а файлы удаляет `_delete_album_files_and_record`.
- **Водяной знак** пользователь включает только для клиентов, которые отбирают фото до оплаты; в публичной галерее знака нет.
  - Посетителю (страница альбома и zip-архив) отдаётся `watermark_url` с **случайным** именем `wm_<uuid>.jpg` и миниатюра рядом с ним, `watermark_thumb_url()` → `wm_<uuid>_thumb.jpg`.
  - Папки `full/` и `thumb/` таких альбомов отдаются только админу (`_protect_watermarked_originals`). Статику на Beget отдаёт сам Flask через Passenger, поэтому `before_request` на неё действует.
  - Кнопка «Применить/Удалить знаки» (`api_sync_watermarks`) пересобирает знаки у ВСЕХ фото альбома (нужно после смены текста, шрифта или размера). Файлы знака удаляет `_remove_watermark_files`. Размер текста — 1/50 ширины фото («средний», выбран владельцем по образцам).
  - Шрифт знака лежит в проекте: `scr/fonts/Manrope-VariableFont_wght.ttf` (OFL, жирное начертание). Системных шрифтов на Linux-хостинге нет: без своего файла Pillow рисует 10px и без кириллицы.
- **Метаданные:** после КАЖДОГО сохранения картинки вызывается `stamp_photo_metadata(path)`. Он переписывает только блок EXIF/XMP JPEG без перекодирования пикселей: удаляет GPS, ставит Artist/Copyright латиницей (`PHOTO_AUTHOR_LATIN` или автотранслит) и XPAuthor кириллицей. Новое место сохранения картинки должно его вызывать. Для уже загруженных файлов есть кнопка в настройках админки (`/admin/settings/stamp-metadata`).
- **Админка, производительность:** не вешать `backdrop-filter` и прочее, что создаёт отдельный графический слой, на элементы, которые повторяются на каждой карточке фото. Из-за этого браузер пересобирал сотни слоёв на каждое движение мыши. У закрытых `.admin-modal` стоит `visibility: hidden`, размытие фона включено только у `.active`. Сетка фото в админке — колонки одной ширины с выравниванием по ширине (дизайн владельца, без его согласия не менять). По его просьбе превью раскладывается тем же правилом, что и сайт (`static/js/masonry-layout.js`, общий для `album.js` и `admin.js`), в 4 колонки, как сайт на ПК, чтобы «как перетащил в админке, так и на сайте». Карточки остаются в разметке по порядку приоритета, на места их ставят `left/top` (`layoutAdminGrid`). Без JS работают CSS-колонки.
- **Вид админки** (выбран владельцем по прототипу, менять только через новый прототип): «Тёмная студия» с кнопкой светлой темы. Цвета — переменные `--a-*` в начале `admin.css`, светлая тема — `<html data-theme="light">`, выбор хранится в localStorage `adminTheme` (ставится скриптом в `<head>` `admin.html`/`login.html`, чтобы не мигало). Блок «ВИД АДМИНКИ» в конце `admin.css` перекрывает старые светлые правила. Иконки — встроенные SVG с классом `.ico` (не эмодзи); кнопки-иконки в списках — `.icon-btn` (+ `.is-danger` для удаления). Галочки настроек — переключатели `input.switch` внутри `label.set-row`. В окнах подвал `.modal-foot` с «Отмена» (`data-close-modal`) и сохранением; выбор файла — `.file-pick` (input невидим, но не `display:none`, иначе у обязательного поля не сработает подсказка браузера). Формат обложки — кнопки `#album-cover-ratio-seg`, значение хранит скрытый `#album-cover-ratio`. Сохранение альбома — `saveAlbumSettings()`; кнопка водяного знака сначала вызывает её, потом пересобирает знаки.
- **Админка на телефоне** (до 760px, блок «ТЕЛЕФОН» в конце `admin.css`; выбрано по прототипу): меню слева скрыто, вместо него нижняя панель `.m-tabbar` (те же `data-target`, что у `.nav-btn`, переключает `activateTab`), в «Ещё» — сайт, тема и выход (`#m-more-template`). Сетка фото — 2 колонки (`ADMIN_PREVIEW_COLUMNS_PHONE`), на ПК по-прежнему 4. Кнопки на карточках фото скрыты: касание открывает шторку `openPhotoSheet` (фокус, пропорция, масштаб, порядок «Раньше / Позже», EXIF, удалить). Шторка ничего не сохраняет сама, а управляет элементами карточки, поэтому сохранение идёт через обычные обработчики; новое действие с фото добавляй в карточку, а в шторку — кнопку, которая его вызывает. Окна на телефоне выезжают снизу. Шрифт полей 16px, иначе iPhone приближает страницу. Без `<meta name="viewport">` в `admin.html` телефон рисует страницу шириной ПК и правила для телефона не включаются.
- **Главная, производительность** (на ноутбуках со встроенной графикой главная лагала; проверено трассировкой Chrome): не двигать за мышью полноэкранные слои — сдвиг слоя на весь экран заставляет видеокарту каждый кадр пересобирать весь экран с размытиями шапки и карточки камеры и зерном (параллакс сетки видоискателя за мышью по этой причине удалён совсем, решение владельца: грузил систему, а его почти не замечали); рамку-курсор сдвигать на целые пиксели (дробный сдвиг перерисовывал уголки каждый кадр); не держать бесконечные анимации `filter` (перерисовка каждый кадр, даже в простое) — «дыхание» делать прозрачностью; пустой полноэкранный `.temp-overlay` при 5600K скрыт (`display: none`). Добавляя эффекты на главную, проверяй, что при движении мыши перерисовываются только маленькие слои.
- **Главная на телефоне:** категории листаются сами по кругу каждые 4,5 с (`AUTOPLAY_STEP_MS`), после свайпа или тапа по точке — пауза 9 с (`AUTOPLAY_RESUME_MS`); пока героя не видно или вкладка свёрнута — ждёт. Свайп тоже по кругу.
- **Кнопка «Связаться» на ПК** (`.cta-dock` в `base.html`, стили — «КНОПКА «СВЯЗАТЬСЯ» НА ПК» в `style.css`, логика — конец `script.js`; выбрана по прототипу `prototypes/contact-button`, «И»): кнопки в шапке нет. Язычок с лапкой у правого края экрана; нажатие выдвигает шторку с контактами (Telegram, ВК, телефон, «Все способы связи»), язычок едет вместе с ней — панель открывается оттуда, где нажал, а не окном по центру. Закрывается повторным нажатием, кликом мимо или Esc. На телефоне — по-прежнему `.mobile-cta` с окном `.contact-modal`.
- **«Пустое место» (заглушка):** строка в `photo` с `is_spacer = 1` и пустыми `file_url`/`thumb_url` (`db/2026-10-04_photo_is_spacer.sql`). Сортируется, перетаскивается и меняет пропорцию как фото (`api_add_spacer`, `api_update_photo`, `api_delete_photo`). На сайте это невидимый `.photo-spacer`, который участвует только в раскладке и только при 3+ колонках. Любой новый запрос, читающий фото как файлы (архивы, EXIF, знаки, счётчики), должен фильтровать `is_spacer = 0`.
- **«Обо мне», первый блок — «Кадр»** (выбран по прототипу, менять вид только через новый прототип): портрет на всю ширину как в видоискателе (HUD, рамка автофокуса `.about-shot__af`, экспонометр, заголовок на фото), под ним текст колонками. Кнопки «Написать» там нет: «Связаться» и так всегда под рукой. Фото — `about_photo_url`, если его нет, аватар (на главной всегда аватар). Рамка ставится чистым CSS: у картинки `object-position` равен точке фокуса, а при `cover` эта точка всегда оказывается в тех же процентах блока, поэтому рамка просто стоит в `left: var(--fx); top: var(--fy)` (на телефоне `--mfx/--mfy`). Настраивается в админке: «Настройки» → «Фото на странице «Обо мне»» (переключатель ПК/Телефон, нажатие на фото ставит точку, рядом превью обоих экранов), сохраняется формой профиля (`admin_settings_profile`).
- **«Обо мне», контакты «Готовы создавать?» — «Список»** (выбран по прототипу, `prototypes/about-contact/`): слева заголовок с «Открыт для съёмок», справа строки «иконка · название · значение · стрелка». Соцсети из `site_socials` (подпись — фильтр `link_handle`: `t.me/x` → `@x`), телефон и почта (`users.email`, поле Email в профиле админки; пустое — строки нет). На ПК клик по телефону/почте копирует их (`[data-copy-phone]`/`[data-copy-email]`, `script.js` 1.8), на телефоне — обычные `tel:`/`mailto:`.
- **Подвал «Волчий след»** (`base.html`, стили в `style.css` «ФУТЕР», логика — `script.js`, «ПОДВАЛ: ВОЛЧИЙ СЛЕД»; выбран по прототипу `prototypes/site-footer`, вариант Н): всё по центру — колос слева от имени (`.footer-sign`: `.wisewolf-seal` — кнопка, рисунок `.holo-icon`; выбран по прототипу `prototypes/footer-wolf`, «Б»: Хоро — волчица урожая), соцсети, правовые ссылки (короткие подписи, полное название в `title`), ©.
