# Сайт-портфолио фотографа

Портфолио с галереей и клиентскими альбомами: клиент открывает свой альбом по
секретной ссылке, отмечает понравившиеся кадры, скачивает фото. Фотограф всё
ведёт из своей админки.

**Стек:** Python, Flask, MySQL (PyMySQL, без ORM), Jinja, обычные JS и CSS без
сборки, Pillow для обработки фото. Хостинг — shared-хостинг с Passenger.

## Что умеет

- **Публичная часть.** Главная с направлениями съёмки, галерея альбомов с
  фильтром по категориям, «Обо мне» (оборудование, награды, контакты), альбом
  с раскладкой «кирпичиками» и лайтбоксом с данными съёмки (EXIF).
- **Клиентские альбомы.** Приватный доступ по токену, отбор фото «сердечком»
  (видно, сколько человек отметили кадр), скачивание архивом, водяной знак до
  оплаты, срок хранения с автоудалением.
- **Админка** (тёмная и светлая темы, отдельный вид для телефона).
  - Загрузка фото с проверкой дубликатов и заменой файла.
  - Порядок перетаскиванием, мобильный кроп с точкой фокуса.
  - «Выбор клиентов» с именами исходных файлов.
  - Место на сервере и вес каждого альбома.
- **Обработка фото.** Миниатюры, пропорции для сетки, мобильные обложки 9:16,
  водяной знак. В метаданных — автор, а геометки удаляются.
- **Правовое (152-ФЗ).** Политики конфиденциальности и cookies, отдельное
  согласие на обработку данных с версиями текста. Шрифты и скрипты лежат на
  своём сервере, без внешних запросов.
- **Безопасность.**
  - Пауза при подборе пароля к админке.
  - Защитные заголовки, проверка адреса после входа.
  - Оригиналы фото со знаком закрыты от прямых ссылок.
  - Превью ссылок для мессенджеров не раскрывают приватные альбомы.

## Структура

- `scr/__init__.py` — всё серверное приложение (роуты, SQL, обработка фото).
- `scr/templates/` — шаблоны страниц.
- `scr/static/` — стили, скрипты, шрифты, иконки. Загруженные фото
  (`static/uploads/`) хранятся только на сервере.
- `db/schema.sql` — структура базы. `db/ГГГГ-ММ-ДД_*.sql` — изменения схемы
  после неё, выполнять по порядку дат.
- `prototypes/` — прототипы дизайна. Каждое решение сначала выбиралось из
  нескольких вариантов в браузере. `_server/fake_site.py` поднимает сайт на
  выдуманных данных без базы.

## Запуск локально

```bash
pip install -r scr/requirements.txt
cp scr/.env.example scr/.env    # и заполнить доступ к MySQL и FLASK_SECRET_KEY
cd scr && FLASK_DEBUG=1 python __init__.py
```

Перед первым запуском:
1. Создайте базу из `db/schema.sql` и примените изменения `db/20*.sql`.
2. Добавьте в `grid_class` строки `ratio-hor`, `ratio-ver`, `ratio-sq`.
3. Добавьте пользователя-админа с `id = 1`.

Посмотреть вёрстку без базы можно на тестовом сайте:
`python prototypes/_server/fake_site.py` → http://127.0.0.1:5090, вход admin / secret.

## Хостинг

Точка входа для Passenger и `.htaccess` лежат на сервере. В репозитории их
образцы: `passenger_wsgi.py.example` и `.htaccess.example`.
